# Make.com Content Factory Builder (КЗ-Строитель)

## Что умеет этот скилл

- Создать новый КЗ для клиента с нуля (по шаблону #1/#2/#3/#4)
- Клонировать существующий КЗ под нового клиента
- Диагностировать проблемы в сценариях
- Объяснить архитектуру любого КЗ из нашей базы
- Настроить расписание и параметры сценариев
- Подключить новые каналы публикации

---

## Стандартная архитектура КЗ

Типовой КЗ состоит из 4–5 нумерованных сценариев, которые работают как конвейер:

```
[#4 Генерация тем] → Data Store → [#1 Пост с фото]
                                  [#2 Видео]
                                  [#3 Публикация / Отчёт]
```

### Сценарий #1 — Пост с фото (основной контент)

**Назначение:** Берёт тему из Data Store, генерирует текст, создаёт изображение, публикует.

**Типичные модули в цепочке:**
1. **Trigger:** Scheduler (каждые 15 мин — 1 час, в окне 08:00–20:00)
2. **Google Sheets / Data Store:** получить следующую необработанную тему
3. **Claude / GPT-4o:** сгенерировать текст поста по теме и промпту
4. **Midjourney / Flux / DALL-E:** сгенерировать изображение по тексту или промпту
5. **HTTP / Telegram / VK / Instagram:** опубликовать пост
6. **Google Sheets / Data Store:** пометить тему как использованную

**Расписание:** `indefinitely`, интервал 900–3600 секунд, restrict по времени суток

**Пример названия:** `#1 | КЗ ПОСТЫ ФОТО Клиент (M)`

---

### Сценарий #2 — Видео

**Назначение:** Создаёт видеоконтент — реалистичное (VEO), анимацию, или берёт готовое видео.

**Варианты подтипов:**
- **VEO ОСНОВНОЙ** — Google VEO 2/3, реалистичное видео
- **VEO АНИМАЦИЯ** — анимированное видео через VEO
- **РЕАЛИСТИЧНОЕ** — через другой генератор (Kling, Runway)
- **ИДЕИ** — генерация идей для видео без самого видео
- **ПАРСИНГ** — взять готовое видео из источника (YouTube и т.д.)

**Типичные модули:**
1. **Trigger:** Scheduler (daily в 11:00/18:00 или indefinitely)
2. **Google Sheets:** взять тему/скрипт
3. **Claude:** написать сценарий или промпт для видео
4. **HTTP (VEO API / FAL AI / Kling API):** запустить генерацию
5. **HTTP:** дождаться результата (polling или webhook)
6. **Google Drive / Dropbox:** сохранить видео
7. **Telegram / VK / YouTube:** опубликовать

**Пример названия:** `#2 | ВИДЕО VEO ОСНОВНОЙ Клиент (М)`

---

### Сценарий #3 — Отчёт / Публикация видео

**Два варианта назначения:**

**3a. Отчёт (Н)** — ежедневный отчёт в Telegram:
1. **Trigger:** daily 08:00–09:00
2. **Google Sheets / Data Store:** подсчитать опубликованные посты за сутки
3. **Telegram:** отправить сводку менеджеру

**3b. Публикация видео** — взять готовое видео и опубликовать:
1. **Trigger:** indefinitely (15 мин) или by webhook
2. **Google Drive / Data Store:** взять следующее готовое видео
3. **Платформа:** опубликовать (VK Видео, YouTube Shorts, TG)

**Пример названия:** `#3 | Отчет Клиент (Н)` или `#3 | Публикация видео Клиент`

---

### Сценарий #4 — Генерация тем

**Назначение:** Ежедневно генерирует 10–30 тем для постов и складывает в Data Store / Google Sheets.

**Типичные модули:**
1. **Trigger:** daily 00:05 или 08:00
2. **Google Sheets:** проверить, нужны ли новые темы (если меньше N тем осталось)
3. **Claude / GPT-4o:** сгенерировать N тем на основе ниши клиента
4. **Google Sheets / Data Store:** записать темы, пометить как новые

**Параметры генерации:**
- Ниша / тематика клиента
- Формат: для ВКонтакте / Instagram / Дзен
- Tone of voice: экспертный / продающий / информационный
- Количество тем за запуск: обычно 10–20

**Пример названия:** `#4 | Генерация тем Клиент`

---

### Сценарий #5 — Дополнительный отчёт (редко)

Встречается у клиентов с высокой нагрузкой (#5 Отчет Урусова). Аналогичен #3 отчёту, но собирает расширенную статистику.

## Архитектура V3/V4 — CONTENT_FACTORY_PRO

Современный формат с нейминг-паттерном:
- `*_CONTENT_FACTORY_PRO v4 CHANNEL_FIRST`
- `*_TOPIC_FEEDER v1`

**Принцип CHANNEL_FIRST:**
- TOPIC_FEEDER генерирует темы → кладёт в очередь (Data Store или Buffer)
- CONTENT_FACTORY_PRO поднимает одну тему → обрабатывает полностью один канал → переходит к следующему
- Это исключает конкурентные запросы и снижает нагрузку на API

**Когда использовать V4:** для клиентов с 3+ каналами публикации (ТГ + VK + Инстаграм + Дзен одновременно)

## Pinterest-сценарий (отдельный)

Pinterest — отдельный сценарий без нумерации, запускается параллельно с основными.

**Типичные модули:**
1. **Trigger:** indefinitely 60–95 минут в окне 07:00–19:00
2. **Google Sheets / Data Store:** взять тему/изображение
3. **HTTP (Pinterest API):** создать пин с описанием, изображением, ссылкой
4. **Google Sheets:** пометить как опубликованное

**Нейминг:** `Pinterest Клиент` или просто `Pinterest` (если клиент один в папке)

---

## Распаковка-сценарий

**Назначение:** Первичное наполнение базы тем и контента. Запускается раз в неделю или вручную.

**Типичные модули:**
1. **Trigger:** weekly (раз в неделю) или on-demand
2. **Google Sheets:** взять данные о клиенте / товаре / SKU
3. **Claude:** сформировать тему/контент из карточки товара или описания услуги
4. **Google Sheets / Data Store:** записать результат в пул тем

**Нейминг:** `Распаковка Клиент` или `КЗ Клиент Распаковка`

## Как создать новый КЗ

### Шаг 1 — Собрать бриф клиента

Нужно знать:
- Ниша и продукты/услуги
- Целевые платформы (ВК, ТГ, Инстаграм, Дзен, Pinterest)
- Желаемая частота постинга (постов в день)
- Тон и стиль
- Источник изображений (ИИ-генерация или свои фото)
- Источник видео (ИИ-генерация или готовые)
- Куда слать отчёт (Telegram ID)

### Шаг 2 — Создать папку в Make.com

```
mcp__8ea23686__folders_create
  name: "Клиент Название"
  teamId: <team_id>
```

### Шаг 3 — Создать Data Store для тем

Структура записи тем:
```json
{
  "id": "auto",
  "topic": "Строка с темой",
  "status": "new | used | skipped",
  "created_at": "datetime",
  "used_at": "datetime | null"
}
```

### Шаг 4 — Создать сценарий #4 (Генерация тем)

Расписание: `{"type": "daily", "time": "00:05"}`

Промпт для генерации тем (шаблон):
```
Ты — контент-менеджер для [НИША].
Создай 15 уникальных тем для постов в [ПЛАТФОРМА].
Темы должны быть:
- Актуальные и интересные аудитории
- Связаны с [ПРОДУКТ/УСЛУГА]
- В формате заголовка (до 10 слов)
Верни JSON-массив строк.
```

### Шаг 5 — Создать сценарий #1 (Посты с фото)

Расписание:
```json
{
  "type": "indefinitely",
  "interval": 3600,
  "restrict": [{"days": [1,2,3,4,5,6,0], "time": ["09:00","20:00"], "months": []}]
}
```

### Шаг 6 — Создать сценарий #2 (Видео) — если нужно

Расписание: `{"type": "daily", "time": "11:00"}` — либо indefinitely если высокая частота

### Шаг 7 — Создать сценарий #3 (Отчёт)

Расписание: `{"type": "daily", "time": "08:00"}`

### Шаг 8 — Создать сценарий Pinterest — если нужно

Расписание:
```json
{
  "type": "indefinitely",
  "interval": 4200,
  "restrict": [{"days": [], "time": ["07:00","19:00"], "months": []}]
}
```

### Шаг 9 — Назвать сценарии по стандарту

```
#1 | КЗ ПОСТЫ ФОТО [Клиент] (M)
#2 | ВИДЕО VEO ОСНОВНОЙ [Клиент] (М)
#3 | Отчет [Клиент] (Н)
#4 | Генерация тем [Клиент]
Pinterest [Клиент]
```

## Паттерны и модули

### Подключения (connections)

- **Claude API** — через HTTP module, метод POST к `api.anthropic.com/v1/messages`
- **GPT-4o** — через OpenAI connection или HTTP
- **Midjourney** — через ImagineAPI или аналог (HTTP)
- **Flux** — через FAL AI API (HTTP)
- **Google Sheets** — нативный модуль Make
- **Google Drive** — нативный модуль Make
- **Telegram** — нативный модуль Make (Bot API)
- **VK** — через HTTP к VK API или нативный модуль
- **Pinterest** — через HTTP к Pinterest API v5
- **VEO** — через Google Cloud Vertex AI (HTTP)

### Data Store vs Google Sheets

| Критерий | Data Store | Google Sheets |
|----------|-----------|---------------|
| Скорость | Быстрее | Медленнее |
| Лимит | 5MB / 50K записей | Нет лимита |
| Редактирование вручную | Неудобно | Удобно |
| Рекомендация | Для очередей тем | Для отчётов и архивов |

### Стандартный промпт для поста (шаблон)

```
Ты — эксперт в [НИША].
Напиши пост для [ПЛАТФОРМА] на тему: [ТЕМА]

Требования:
- Объём: 800–1200 символов
- Стиль: [экспертный / продающий / информационный]
- Начни с цепляющего заголовка или вопроса
- Добавь 3–5 хэштегов в конце
- Не используй эмодзи в тексте (только если разрешено)

Верни только текст поста без пояснений.
```

### Обработка ошибок

- Всегда добавляй `error handler` на модули с API-вызовами
- При ошибке генерации изображения: логировать в Google Sheets, пропустить тему
- При ошибке публикации: отправить уведомление в Telegram менеджеру

### Оптимизация операций

- Один запуск сценария = один пост (не пакетная обработка)
- Интервал минимум 900 секунд (15 мин) — лимит Make.com
- При высокой частоте (1 пост/час) используй 3600 сек интервал
- При низкой частоте (2–3 поста/день) используй 8–12 часов интервал

## Диагностика проблем

### Сценарий не запускается
1. Проверить активен ли сценарий (`isEnabled`)
2. Проверить расписание — не попадает ли вне временного окна
3. Проверить баланс Make.com операций

### Темы заканчиваются
1. Проверить сценарий #4 — запускается ли он
2. Проверить фильтр выбора тем — возможно все темы помечены как "used"
3. Сбросить статус части тем на "new" в Data Store

### Изображения не генерируются
1. Проверить баланс токенов Midjourney / FAL / Flux
2. Проверить подключение (connection) к сервису
3. Проверить промпт — нет ли запрещённых слов

### Посты не публикуются
1. Проверить токен Telegram/VK/Instagram (не истёк ли)
2. Проверить формат контента для платформы
3. Посмотреть историю выполнений на предмет ошибок

## Быстрые команды MCP

```
# Получить список сценариев в папке
mcp__8ea23686__scenarios_list folderId=XXXXX

# Активировать сценарий
mcp__8ea23686__scenarios_activate scenarioId=XXXXXXX

# Деактивировать сценарий
mcp__8ea23686__scenarios_deactivate scenarioId=XXXXXXX

# Запустить сценарий вручную
mcp__8ea23686__scenarios_run scenarioId=XXXXXXX

# Посмотреть последние запуски
mcp__8ea23686__executions_list scenarioId=XXXXXXX

# Создать папку
mcp__8ea23686__folders_create name="Клиент" teamId=XXX
```
